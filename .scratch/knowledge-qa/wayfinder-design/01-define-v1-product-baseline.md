# 确定通用企业文档问答 V1 产品基线

Type: grilling
Status: resolved
Blocked by: none

## Question

基于现有 RuoYi backend/frontend 二开时，V1 要为谁解决什么问题、包含哪些能力、以什么边界和指标判断内部试点成功？

## Answer

### 定位与角色

V1 是小范围真实使用的内部试点版，目标是跑通多类企业文档的解析、切块、嵌入、检索与流式生成。所有已登录用户都是普通用户；RuoYi 中被授予相应角色的用户同时是知识管理员。所有知识管理员可管理全部知识库、企业文档和反馈，不设知识库所有者。

### 知识库与企业文档

- 知识管理员可创建、修改和级联删除知识库。名称不区分大小写且全局唯一；状态为可用、删除中或删除失败。
- 每篇企业文档只属于一个知识库。同一知识库内原始文件名不区分大小写且唯一，不同知识库可重名。
- 支持带文本层的 PDF、DOCX、MD、TXT；不支持 OCR、图片、表格文件、网页、第三方知识源、压缩包和文件夹。
- 支持批量上传。上传前整批校验，只要与现有文档或批次内部重名，就拒绝整个请求并列出冲突；校验通过后，各文件独立异步处理。
- 文档状态为处理中、可用、处理失败或删除中。整篇解析、切块、嵌入和向量发布全部成功后才可检索；失败时清理本次数据，重试整篇处理。
- 删除文档立即退出检索并异步清理原文件、片段和向量。删除知识库时自动级联清理内部文档；失败后保持不可用并允许重试。
- 原文件存入 MinIO，业务记录和对象键存入 MySQL，向量与来源元数据存入 Milvus。

### 问答体验

- 普通用户能看到所有可用知识库的名称与描述，但不能浏览文档列表、预览或下载原文。
- 新建会话时必须选择一个知识库；标题默认取第一个问题并可修改。一个会话包含多条记录，但每次问题独立检索，不使用历史上下文，也不跨知识库检索。
- 空知识库仍可选择和创建会话，提问时提示“该知识库暂无可用文档”。处理中或失败的文档不参与检索。
- 回答采用简洁中文，先给结论再补必要说明。检索证据不足时必须拒答，不能使用模型自身知识补答。
- 使用 SSE 流式输出，浏览器连接 Java，由 Java 转发 Python 的 `started`、`delta`、`completed`、`refused`、`error` 事件。每个用户同时只能生成一个回答。
- 用户可停止生成；已输出内容保存为“已停止”。系统中途失败时保存残缺回答并标记“未完成”。完整、未完成和已停止记录均默认永久保留。

### 反馈与日志

- 普通用户可按答案错误、未找到答案、回答不完整、其他提交反馈并附可选说明。提交反馈即授权知识管理员查看该条问题、回答和排障元数据。
- 知识管理员可将反馈标记为待处理或已处理并填写内部备注；V1 不做管理员回复、通知、自动重跑或外部工单流转。
- 未提交反馈的问答正文对知识管理员不可见。技术日志记录请求 ID、用户和实例标识、阶段、文档/片段 ID、分数、耗时、模型请求 ID、SSE 进度、错误栈和重试，但不记录问题、片段、完整提示词或生成正文。
- 用户删除自己的会话或问答记录时一并删除反馈正文，只保留无内容的操作审计。删除企业文档不删除既有问答历史和反馈。

### RAG 与数据边界

- Python 使用通用文本切块：优先标题和自然段，过长时按可配置长度和重叠切分；保存文档 ID、原始文件名、片段顺序和 PDF 页码等未来引用所需元数据。
- V1 使用本地 `bge-m3` 稠密向量、Milvus 单 Collection 和阿里云百炼 `qwen-plus`，不做关键词检索、重排和引用展示。
- 每条向量携带 `knowledgeBaseId`，检索必须强制过滤当前会话绑定的知识库，并用真实 Milvus 集成测试守住不跨库召回的不变式。
- 上传页面提示用户问题和召回片段会发送至百炼。V1 不做敏感文档拦截、脱敏、审批或等级字段，由知识管理员自行判断。
- 自动化测试使用假模型；不增加真实百炼 API 连通性测试，真实通道由部署后的人工问答验收确认。

### 试点指标

- 正式支持中文文档和中文问答；英文仅作非承诺兼容。
- 容量目标：1,000 篇文档、单文件 50 MB、总文件量 20 GB、50 名普通用户、5 路问答并发。
- 95% 的 50 MB 内文档在 5 分钟内完成异步入库；95% 的问答在 5 秒内开始输出、15 秒内完成，百炼异常除外。
- 人工标注测试集至少覆盖可回答、跨片段、无答案和语义改写问题。可回答问题至少 80% 结论正确，不可回答问题至少 90% 正确拒答，回答不得引入召回内容之外的关键事实。

### 技术边界

RuoYi Java/Vue 负责认证、角色、知识库、企业文档记录、文件存储、会话、问答历史、反馈和客户端 API；Python 负责解析、切块、嵌入、检索和生成。两者通过 Nacos 发现的内部 HTTP 接口协作。V1 页面为问答工作台、会话历史、知识库管理、库内文档管理和反馈处理，沿用现有登录、用户和角色管理页面。
