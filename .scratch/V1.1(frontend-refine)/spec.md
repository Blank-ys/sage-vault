# Sage Vault V1.1 前端体验重塑

Status: ready-for-agent

## Problem Statement

Sage Vault 当前把知识问答与 RuoYi 管理功能放在同一套后台布局中。普通用户登录后先看到模板首页，知识问答仍以卡片式管理页面呈现，会话、知识库选择、问答正文和个人操作缺少清晰的信息层级；知识管理员和系统管理员也缺少从问答工作状态进入管理能力、再返回原会话的连续路径。

现有管理页面保留了较强的 RuoYi 模板观感，管理概览仍展示若依宣传和已不准确的技术栈内容。知识库管理、企业文档和问答反馈与系统管理、系统监控在视觉密度、页面标题、筛选、操作和表格呈现上不一致。移动端会话导航、个人中心的归属、管理入口权限、生成期间离开等关键交互也没有形成明确承诺。

V1.1 需要在不改变 Java 后端接口、业务状态、权限事实和问答生命周期的前提下，将登录后的体验明确分为问答工作台与管理后台。页面布局和视觉语言参考用户提供的 Ragent 问答页、聊天页、管理后台和知识库管理页截图，但不得复制参考产品的品牌、虚构功能或不存在的数据。

## Solution

所有已登录内部用户默认进入独立、全屏的问答工作台。工作台使用左侧会话栏和右侧问答主区域：用户可以新建会话、为新会话选择知识库、按标题过滤会话、阅读历史、提问、停止生成、重命名或删除会话，并对回答提交现有反馈。个人中心、布局设置、锁定屏幕和退出登录集中在左下角头像区域，消息通知通过同一区域的铃铛进入。

拥有至少一个管理菜单权限的用户可以通过问答工作台中的“管理后台”进入管理概览。管理后台继续使用 RuoYi 动态菜单和权限体系，但采用深色侧栏、简洁顶栏、面包屑、页面标题、高密度内容区和统一的表格/表单视觉。管理概览按用户已有菜单权限展示管理功能导航，不新增统计接口。用户可从后台返回离开前的问答会话。

个人中心使用独立账号页面，不依附问答侧栏或管理侧栏，并按进入来源返回对应工作空间。桌面端与移动端均提供完整导航；现有深色模式继续适配。所有改动只重塑前端路由、布局、视觉和交互组织，不改变后端业务交互。

## User Stories

1. As an 已登录内部用户, I want 登录后默认进入问答工作台, so that 我可以立即开始知识问答而不是先经过管理模板首页。
2. As an 已登录内部用户, I want 访问兼容首页路径时进入问答工作台, so that 旧入口不会把我带到管理概览。
3. As an 已登录内部用户, I want 看到 Sage Vault 的产品标识和“企业知识问答”定位, so that 我能明确当前产品和任务。
4. As an 已登录内部用户, I want 问答工作台使用独立全屏布局, so that 后台导航和页签不会干扰阅读与提问。
5. As an 已登录内部用户, I want 从左侧快速发起新会话, so that 新问答始终有清晰入口。
6. As an 已登录内部用户, I want 新建会话时在主区域选择知识库, so that 每次会话都有明确检索边界。
7. As an 已登录内部用户, I want 在选择知识库前不能发送问题, so that 系统不会创建检索边界不明的问答记录。
8. As an 已登录内部用户, I want 已有会话只读展示其知识库名称, so that 我能随时确认回答来自哪个知识库。
9. As an 已登录内部用户, I want 更换知识库时必须新建会话, so that 历史问答的检索边界不会被改变。
10. As an 已登录内部用户, I want 会话标题和知识库名称在顶部形成两级信息, so that 会话主题与检索范围不会混淆。
11. As an 已登录内部用户, I want 长知识库名称被安全省略并可查看完整名称, so that 标题区不会溢出或遮挡内容。
12. As an 已登录内部用户, I want 已删除知识库的会话继续显示原知识库名称和“已删除”状态, so that 历史来源仍然清楚。
13. As an 已登录内部用户, I want 已删除知识库的会话禁用提问, so that 系统不会暗中切换检索范围。
14. As an 已登录内部用户, I want 按当前加载会话的标题即时过滤会话, so that 我能快速找到历史会话。
15. As an 已登录内部用户, I want 会话搜索不读取问题或回答正文, so that 搜索能力不扩大正文处理和隐私范围。
16. As an 已登录内部用户, I want 会话搜索词不被持久化, so that 临时查找不会留下不必要的浏览器记录。
17. As an 已登录内部用户, I want 从会话省略号菜单重命名会话, so that 侧栏保持简洁但现有整理能力不丢失。
18. As an 已登录内部用户, I want 从会话省略号菜单删除会话并二次确认, so that 破坏性操作不会被误触。
19. As an 已登录内部用户, I want 用户问题靠右、回答正文靠左展示, so that 对话角色一眼可辨。
20. As an 已登录内部用户, I want 回答区继续正确展示 Markdown, so that 列表、代码、表格和引用保持可读。
21. As an 已登录内部用户, I want 输入区固定在易于到达的位置, so that 长回答场景下仍能连续提问。
22. As an 已登录内部用户, I want 使用 Enter 发送并使用 Shift+Enter 换行, so that 现有高效输入方式保持不变。
23. As an 已登录内部用户, I want 生成期间看到停止按钮, so that 我可以显式停止不再需要的回答。
24. As an 已登录内部用户, I want 停止生成仍调用现有业务取消接口, so that 连接断开不会被误当作主动停止。
25. As an 已登录内部用户, I want 回答下方通过反馈图标打开现有反馈对话框, so that 我仍能选择反馈类型、填写说明并确认共享正文。

30. As an 已登录内部用户, I want 左下角头像菜单包含个人中心、布局设置、锁定屏幕和退出登录, so that 个人操作集中且可预测。

## Implementation Decisions

- 前端继续作为唯一浏览器应用，复用现有 RuoYi 认证、用户、角色、动态菜单、权限拦截、全局通知、锁屏、主题和 Element Plus 基础能力。
- 登录后的界面分为问答工作台和管理后台两个工作空间；个人中心是独立账号页面，不是第三个业务工作空间，也不以弹窗呈现。
- 知识问答正式路径保留为 `/sage/qa`。`/index` 和根入口跳转到 `/sage/qa`，普通登录默认进入 `/sage/qa`。
- 管理概览正式路径为 `/admin/index`。它不使用独立 Dashboard 权限标识，而以“用户拥有至少一个后台动态菜单权限”为访问门槛。
- 登录前访问受保护深链接时继续携带原目标；登录和权限路由注册完成后，有权限则恢复原页面。普通登录不携带管理深链接时仍进入问答工作台。
- 无任何管理菜单权限的用户直接访问管理概览或管理后台入口时，返回问答工作台并显示一次“暂无管理后台权限”。隐藏按钮不是授权机制，Java 响应和现有菜单权限仍是最终权威。
- “管理后台”按钮位于问答侧栏上方的新建会话区域，仅对拥有任一后台动态菜单权限的用户显示。
- 问答工作台采用独立全屏布局，不渲染管理后台的导航栏、侧栏、面包屑或多页签条。
- 问答侧栏包含 Sage Vault 品牌区、新建会话入口、管理后台入口、按标题过滤会话的搜索框、会话列表和底部账号区域。
- 会话搜索只过滤当前已由现有接口加载的会话标题，不搜索问题或回答正文，不新增后端接口，不持久化搜索词。
- 会话行将重命名和删除收敛到省略号菜单。删除继续使用二次确认，不新增置顶、分享、导出或其他后端未支持能力。
- 新对话状态在主区域选择知识库。未选择知识库时输入不可提交；选定后按现有流程在首次提问时创建会话。
- 已有会话顶部使用两行标题：会话标题为主信息，知识库名称为只读检索边界。不得在已有会话中切换知识库。
- 知识库名称过长时截断并通过悬停提示完整名称。知识库被删除时展示原名称和“已删除”，保留历史阅读并禁用新提问。
- 新对话标题使用“从企业知识中找到答案”，说明使用“选择知识库，答案将仅基于其中的可用企业文档生成”。不展示硬编码推荐问题或“深度思考”等不存在的能力。
- 聊天正文参考用户提供的聊天页布局：用户问题靠右，回答内容靠左，输入区位于主区域底部；保留现有 Markdown、流式状态、Enter/Shift+Enter、停止生成和历史状态语义。
- 每条回答只提供反馈图标入口并配 tooltip，点击后复用现有反馈对话框。已反馈记录显示不可点击状态；不新增复制、点赞或点踩。
- 问答页左下角使用头像和昵称打开个人菜单，保留个人中心、布局设置、锁定屏幕和退出登录；同一区域右侧使用独立铃铛打开现有消息通知能力。
- 桌面端问答侧栏可收起，收起偏好可以持久化；不得持久化问题、回答或企业文档正文。移动端侧栏以抽屉呈现，选择会话后自动关闭。
- 从问答进入管理后台时记录可恢复的问答位置，仅记录会话标识或路由位置，不缓存问答正文。后台“返回问答”优先恢复该位置，无可恢复位置时进入新对话状态。
- 用户在生成期间切换会话、进入管理后台、打开个人中心或进行其他会卸载当前问答的导航时，先确认“停止生成并离开”。确认后调用现有显式停止接口；只有停止成功后导航，失败则留在当前页并提示错误。
- 管理后台继续由 RuoYi 动态菜单提供菜单层级、顺序、标题、图标和权限事实。前端不得硬编码一份平行菜单或管理员名单。
- 管理后台侧栏品牌为“Sage Vault / Management Console”，收起时只展示现有 Logo。管理概览作为固定入口展示，其余管理菜单继续按动态菜单权限显示。
- 管理后台顶栏左侧提供授权管理菜单搜索；右侧依次提供返回问答、消息通知和头像菜单。移除参考站 GitHub Star，也不散放全屏、组件尺寸等工具图标。
- 后台不显示可见多页签条，主导航使用侧栏、面包屑和页面标题。若页面缓存仍需要现有内部状态，可以保留实现但不呈现页签 UI。
- 管理概览移除若依宣传、外链、版本营销和过时技术栈内容，改为 Sage Vault 欢迎信息与按授权动态菜单生成的紧凑管理功能导航。
- 管理概览不新增统计接口，不展示知识库数、文档数、用户数或其他无法由现有接口可靠提供的统计卡片。
- 管理功能导航按动态菜单顺序组织，展示图标、菜单名称和简短职责说明；不展示无权菜单，点击进入对应现有管理路径。
- 知识库管理、企业文档、问答反馈和管理概览进行针对性页面结构调整。知识库管理使用面包屑、标题说明、真实操作区、表格与分页，不复制参考页的 Embedding 模型、Collection、负责人或统计字段。
- 企业文档保留知识库选择、百炼出网提示、批量选择与上传流程；问答反馈保留现有处理流程、正文授权和隐私边界。
- 系统管理、系统监控及其详情、日志、分配等子页面统一应用新后台外壳、颜色、间距、表格、分页、表单和弹窗视觉，但保留现有信息架构、查询字段、按钮权限和后端接口。
- 后台列表页只统一视觉语言，不强制统一筛选位置。少量条件可与操作区同排；条件较多时保留独立筛选行，窄屏允许换行。
- 个人中心使用独立路由页面，继续提供现有资料、头像和密码功能。页面使用轻量顶栏与主体内容，不显示会话侧栏、管理侧栏或多页签。
- 个人中心记录进入来源：从问答进入则返回问答，从管理后台进入则返回原后台位置；直接访问时提供有效的默认返回问答行为。
- 问答工作台的布局设置只展示通用主题能力。后台导航模式、侧栏和其他仅管理后台生效的设置只在管理后台展示。
- 两个工作空间和个人中心继续使用现有主题状态与 Element Plus CSS 变量支持深色模式。参考截图是浅色模式的视觉基准，不在业务组件中散落不可切换的浅色常量。
- 视觉实现参考截图的布局比例、信息层级、间距、阴影、深色侧栏和交互位置，使用现有 Sage Vault 品牌资产与 Element Plus 图标。
- 不复制 Ragent 品牌、机器人 Logo、GitHub Star、模型名称、示例问题或示例数据；不增加图片、字体或 UI 框架依赖。
- 不改变现有 Java API、SSE 事件、反馈契约、权限标识、菜单数据、知识库绑定、会话状态、问答状态和删除语义。
- 不创建 Sage Vault 业务全局 store。跨页面恢复只保存最小导航状态，后端业务状态继续权威。

## Testing Decisions

- 最高验证 seam 是真实浏览器登录前端，经现有 Gateway 和 Java 权限/业务 API 验证完整用户承诺。组件级检查和构建只能辅助定位，不能替代该 seam。
- 浏览器验收至少覆盖四类权限组合：无管理权限的普通用户、仅知识管理权限用户、仅系统管理权限用户、同时拥有两类管理权限用户。
- 验证普通登录、`/index` 兼容入口和根入口均进入 `/sage/qa`；验证 `/admin/index` 的授权访问和无权限回退。
- 验证登录前访问有权限管理深链接可以在登录后恢复；无权深链接不能绕过动态菜单和 Java 权限。
- 验证问答新会话选择知识库、首次提问创建会话、已有会话只读知识库、已删除知识库历史可读且禁止提问。
- 验证会话标题过滤只作用于已加载标题，清空搜索恢复列表，不搜索或持久化问答正文。
- 验证重命名、删除二次确认、流式回答、停止生成、失败/拒答/已停止/未完成展示和反馈对话框仍通过现有接口工作。
- 验证生成期间切换会话、进入后台或个人中心会触发离开确认；取消确认留在原页，停止失败不导航，停止成功后才导航。
- 验证进入后台再返回问答恢复原会话；无恢复位置时进入新对话，且恢复机制不写入正文持久化存储。
- 验证管理概览按四类权限账号展示正确管理入口、顺序和跳转，不展示无权入口或伪造统计。
- 验证系统管理、系统监控、知识库管理、企业文档和问答反馈的现有查询、分页、增删改、上传、反馈处理和按钮权限未被换肤破坏。
- 验证个人中心从问答和后台进入时使用独立外壳并正确返回来源；直接访问、刷新、头像修改和密码修改仍可使用。
- 验证消息通知、锁定屏幕、退出登录、主题切换和受限布局设置在对应外壳中的入口与行为。
- 浏览器视觉验收至少使用桌面 `1440x900` 和移动端 `390x844` 视口，补充一个中等宽度视口检查换行；对问答新对话、已有聊天、管理概览、知识库管理、典型系统管理页和个人中心截图检查。
- 视觉验收检查侧栏收起/展开、移动抽屉、长会话标题、长知识库名称、空列表、加载、错误、禁用、弹窗和深色模式，确保无文字溢出、控件遮挡、非预期横向滚动或动态内容引起的布局跳动。
- 前端改动至少运行生产构建。仓库当前没有前端单元测试、Vitest、Cypress 或 Playwright 资产，因此本规格不把不存在的测试命令写成已具备能力；实现工单若引入自动化浏览器资产，必须说明 owner、运行入口和环境依赖。
- 浏览器交互优先使用真实测试账号和真实 Java 接口。无法启动完整后端时，可以用局部视觉检查辅助开发，但最终验收必须明确报告未覆盖的真实接口与权限风险。
- 测试断言公开页面行为、路由结果、可见权限、API 结果和用户可观察状态，不断言 Vue 私有方法、组件内部 ref、Pinia 内部结构或具体 CSS 类名。

## Out of Scope

- 修改 Java、Python、数据库 schema、菜单 seed、Nacos 配置或任何现有 API/SSE wire contract。
- 新增管理统计接口、Dashboard 指标、知识库聚合统计或伪造占位数据。
- 新增推荐问题、示例问题管理、深度思考模式、回答复制、点赞、点踩、分享、导出或会话置顶。
- 新增知识库搜索后端接口；知识库管理没有真实查询能力时不展示不可用搜索框。
- 更改会话绑定知识库、问答状态机、反馈授权、正文隐私、显式取消或删除语义。
- 重组后端动态菜单、改变菜单顺序、复制管理员角色名单或以隐藏按钮替代授权。
- 重写系统管理和系统监控的信息架构或业务操作；这些页面只统一外壳和视觉。
- 复制参考站的品牌、Logo、GitHub Star、模型信息、示例内容、统计字段或产品文案。
- 引入新的 UI 框架、字体、图标库、图片生成资产或其他前端依赖。
- 为本次改版创建跨 feature 的业务状态层或把问答正文写入持久化浏览器存储。
- 修改登录页和注册页的整体视觉，除非实现工作中发现为支持默认路由所需的最小行为调整。
- 生产部署、公开发布、依赖升级或版本基线变更。

## Further Notes

- 视觉参考来自用户提供的管理后台、知识库管理、智能问答新对话和实际聊天页面截图。截图只提供布局与视觉方向，Sage Vault 的现有领域词汇、业务规格、Java 权限和接口行为优先。

- 本规格涉及布局与导航边界，但不改变系统职责、数据所有权或难以逆转的集成方式，当前不新增 ADR。
