# Java-Python Knowledge QA Service Contract

## Purpose And Authority

This document defines the version 1 HTTP boundary between the Java business platform and the Python AI service for Knowledge QA. Both services MUST implement this contract and MUST NOT hard-code a peer host or port.

Java is authoritative for Regulation Documents, document state, and Authorization Claims. Python owns retrieval, generation, ingestion processing, and visibility reindexing. Python MUST apply the supplied Authorization Claims before a Chunk is retrieved or supplied to an LLM.

The contract uses the domain terms defined in `CONTEXT.md`. It does not define user-facing Java APIs, object-storage transfer details, Milvus schemas, or a message queue.

## Transport And Service Discovery

- All requests and responses use HTTP, `Content-Type: application/json`, and UTF-8 JSON bodies.
- Java registers the callback service as `knowledge-qa-business`; Python registers the AI service as `knowledge-qa-ai` in the same configured Nacos namespace and group.
- Java resolves `knowledge-qa-ai` through Nacos for `/answer`, `/ingest`, and `/reindex-visibility`. Python resolves `knowledge-qa-business` through Nacos for callbacks.
- Nacos resolves addresses only; it does not authenticate callers. Neither service may substitute a configured host:port for discovery.
- Callback endpoints are direct service-to-service endpoints and bypass the user JWT gateway filter. They require the callback authentication defined in this document.

## Common Conventions

### Identifiers, Times, And Retries

- `requestId` is a UUID generated by the caller. It is required on every request and response, correlates logs, and is the idempotency key for an asynchronous task.
- `documentId` is Java's stable identifier for a Regulation Document. `userId` is Java's stable identifier for the current user.
- Times, when present, use ISO-8601 UTC strings, for example `2026-07-23T09:15:00Z`.
- A repeated `/ingest` or `/reindex-visibility` request with the same `requestId` and identical payload MUST return the original `202 Accepted` result without scheduling duplicate work. Reuse of a `requestId` with a different payload MUST return `409 Conflict`.
- A callback is idempotent by `(requestId, documentId, callback type)`. Java matches callbacks against the recorded task, including a completed task. It MUST accept a replay containing the same terminal result without a second state transition, and MUST return `409 Conflict` for a conflicting result.

### Errors

Every non-2xx response has this body:

```json
{
  "code": 400,
  "message": "documentId must be provided",
  "requestId": "c7ae2e8a-7778-4f64-9a26-330dc0d3b75e"
}
```

`code` equals the HTTP status. Implementations MUST NOT include Regulation Document content, Authorization Claims, visible tags, or the callback secret in an error message unless the value was already included in the request.

`400 Bad Request` means a schema or state-value violation; `401 Unauthorized` means callback authentication failed; `404 Not Found` means an unknown document or task; `409 Conflict` means an invalid state transition, request-id reuse conflict, or conflicting callback replay; and `5xx` means the receiver could not complete processing.

## Shared Schemas

### Authorization Claims

Java creates Authorization Claims from its authenticated user, roles, and departments. Python MUST use `tags` as the only authorization input to retrieval: a Chunk is eligible only when `chunk.visibleTags` intersects `authorizationClaims.tags`. Python MUST NOT infer, expand, replace, or log these tags. Java MUST include `PUBLIC`.

```json
{
  "userId": "100",
  "tags": ["PUBLIC", "ROLE_HR", "DEPT_200"]
}
```

All tag values are non-empty strings. A Sentinel Tag MUST not intersect any user Authorization Claims. It makes the Regulation Document unavailable to every user until its visibility reindexing succeeds.

### Citation

```json
{
  "documentId": "regulation-2026-leave",
  "documentTitle": "Leave Management Regulation",
  "chapter": "Chapter 3",
  "section": "Section 2",
  "article": "Article 12",
  "page": 8
}
```

`documentId` and `documentTitle` are required. At least one of `chapter`, `section`, `article`, or `page` is required. A page-level fallback Citation may set `chapter`, `section`, and `article` to `null`.

## Java To Python Requests

### Answer A Knowledge QA Request

`POST /answer`

```json
{
  "requestId": "c7ae2e8a-7778-4f64-9a26-330dc0d3b75e",
  "question": "How many days of maternity leave are available?",
  "authorizationClaims": {
    "userId": "100",
    "tags": ["PUBLIC", "ROLE_HR", "DEPT_200"]
  }
}
```

Success response (`200 OK`):

```json
{
  "requestId": "c7ae2e8a-7778-4f64-9a26-330dc0d3b75e",
  "answer": "The regulation provides 158 days of maternity leave.",
  "citations": [
    {
      "documentId": "regulation-2026-leave",
      "documentTitle": "Leave Management Regulation",
      "chapter": "Chapter 3",
      "section": "Section 2",
      "article": "Article 12",
      "page": 8
    }
  ],
  "refused": false
}
```

When there is no sufficiently reliable, authorized evidence, Python returns `200 OK` with `refused: true`, `answer` set to the non-empty refusal message, and an empty `citations` array. When `refused` is `false`, `answer` is a non-empty answer and `citations` is non-empty. Python MUST NOT use unauthorized Chunks in retrieval, LLM context, answers, or Citations, and MUST NOT use general LLM knowledge as a fallback.

### Start Document Ingestion

`POST /ingest`

```json
{
  "requestId": "dc3a4f1e-2a83-454f-9b4e-5e5780b871b4",
  "documentId": "regulation-2026-leave",
  "sourceObjectKey": "regulations/regulation-2026-leave.pdf",
  "visibleTags": ["PUBLIC"]
}
```

`sourceObjectKey` is an opaque Java-owned object-storage key; Python MUST NOT accept a URL instead. Python responds after accepting the asynchronous task:

```json
{
  "requestId": "dc3a4f1e-2a83-454f-9b4e-5e5780b871b4",
  "accepted": true
}
```

The response is `202 Accepted`. When Java creates the Regulation Document, it sets `ingestStatus=PROCESSING` and `visibilityStatus=SYNCED`. If the trigger itself cannot be delivered, Java sets `ingestStatus=FAILED`; it MUST NOT wait for a callback that cannot occur. Python reports a successfully accepted task's terminal result to `/callback/ingest`.

### Start Visibility Scope Reindexing

`POST /reindex-visibility`

```json
{
  "requestId": "bca389ce-9dc6-45c9-9525-1d1df9940bf7",
  "documentId": "regulation-2026-leave",
  "visibleTags": ["ROLE_HR", "DEPT_200"]
}
```

Java MAY send this request only when `ingestStatus=READY` and `visibilityStatus=SYNCED`. Before triggering Python, Java synchronously replaces the Regulation Document's Chunk tags with a Sentinel Tag and sets `visibilityStatus=UPDATING`. If the trigger itself cannot be delivered, Java sets `visibilityStatus=FAILED`, retains the Sentinel Tag, and MUST NOT restore or write normal tags. Python returns the same `202 Accepted` body as ingestion and reports the terminal result to `/callback/visibility`.

## Python To Java Callbacks

### Authentication

Every callback MUST include:

```text
X-Knowledge-QA-Callback-Secret: <shared secret>
```

The secret comes only from deployment configuration. Java MUST compare it in constant time and MUST NOT log or return it. A missing or invalid secret receives `401 Unauthorized`; Java MUST NOT update any document state for that request.

### Report Ingestion Completion

`POST /callback/ingest`

```json
{
  "requestId": "dc3a4f1e-2a83-454f-9b4e-5e5780b871b4",
  "documentId": "regulation-2026-leave",
  "status": "READY",
  "failureReason": null,
  "manualNormalizationRequired": false
}
```

`status` is `READY` or `FAILED`. `failureReason` is required and non-empty for `FAILED`, and `null` for `READY`. Java accepts this callback only for the matching recorded ingestion task. For its active task, it transitions `ingestStatus` from `PROCESSING` to the reported terminal status; for the same terminal replay, it makes no state change. This callback MUST NOT change `visibilityStatus`.

`manualNormalizationRequired=true` is allowed only with `READY` and means Python used the page-level fallback; it does not make ingestion fail.

### Report Visibility Reindexing Completion

`POST /callback/visibility`

```json
{
  "requestId": "bca389ce-9dc6-45c9-9525-1d1df9940bf7",
  "documentId": "regulation-2026-leave",
  "status": "SYNCED",
  "failureReason": null
}
```

`status` is `SYNCED` or `FAILED`. `failureReason` is required and non-empty for `FAILED`, and `null` for `SYNCED`. Java accepts this callback only for the matching recorded visibility task. For its active task, it transitions `visibilityStatus` from `UPDATING` to the reported terminal status; for the same terminal replay, it makes no state change. This callback MUST NOT change `ingestStatus`.

On `SYNCED`, Python has written the requested visible tags. On `FAILED`, Java MUST retain the Sentinel Tag, MUST NOT restore old or proposed tags, and the Regulation Document remains unavailable to retrieval.

## Python Extension Seams

Python exposes replaceable interfaces whose adapters do not alter this HTTP contract:

```python
class Retriever:
    def retrieve(self, question: str, authorization_claims: AuthorizationClaims) -> list[Chunk]:
        ...


class LLMClient:
    def generate(self, question: str, context: list[Chunk]) -> str:
        ...
```

The default `LLMClient` adapter is configurable for DeepSeek. Contract and boundary tests MUST inject a fake `LLMClient`; they MUST NOT send external LLM requests. Authorization boundary tests use a real Milvus instance so they verify the actual tag-intersection filter.

## Contract Acceptance Tests

- Nacos resolves Java to `knowledge-qa-ai` and Python to `knowledge-qa-business`; no test or production configuration requires a peer host or port.
- `/answer` forwards Java's Authorization Claims unchanged to `Retriever`; `Retriever` filters only by their `tags`. Excluded and Sentinel-Tag Chunks never appear in retrieval, LLM context, answers, or Citations. Insufficient evidence produces a Refusal with a non-empty `answer` and empty `citations`.
- `/ingest` and `/reindex-visibility` return `202 Accepted`, deduplicate identical retry requests, and reject conflicting `requestId` reuse.
- Java marks an undeliverable trigger as the corresponding `FAILED` state and does not wait for a callback. An undeliverable visibility trigger retains the Sentinel Tag.
- An authorized, matching ingestion callback changes only `ingestStatus` from `PROCESSING` to `READY` or `FAILED`; a visibility callback changes only `visibilityStatus` from `UPDATING` to `SYNCED` or `FAILED`.
- A visibility request is rejected unless `ingestStatus=READY` and `visibilityStatus=SYNCED`; Java writes the Sentinel Tag before accepting the asynchronous transition.
- Missing or invalid callback secrets return `401 Unauthorized` and leave state unchanged. Duplicate terminal callbacks are safe; conflicting or unmatched callbacks return `409 Conflict` and leave state unchanged.
- A failed visibility callback retains the Sentinel Tag. No user, including one previously authorized, can retrieve that Regulation Document.
