# 生成走外部 LLM API,权限泄露与数据出网是两件事,provider 抽象化

## Status

accepted

## 背景:两种"泄露"必须分开

CONTEXT/spec 里"无权内容绝不外泄,哪怕只是喂给大模型"这句话,压着两种**完全不同**的泄露,不拆开就会误判"外部 API 违背安全约束":

- **① 跨用户的权限泄露**:当前用户**无权**看的文档,其内容不得被召回、更不得进入 prompt。主体是"这个没权限的用户"。靠**标签求交在调用 LLM 之前**就滤掉无权 chunk 来保证。**与 LLM 部署在哪儿无关**——只要送进 prompt 的永远只是当前用户有权看的 chunk,接本地模型还是外部 API 都成立。这才是 ADR-0001 与 Seam 2 守护的那条不变式。
- **② 数据出公司网**:把制度原文(哪怕是有权用户有权看的那部分)发到第三方 API,等于语料离开公司边界。这是**供应商信任问题**,与权限无关。

## 决策

第一版**生成环节调用外部 LLM API**(MVP 默认适配器 = DeepSeek)。这不触碰 ①——权限过滤在调用 LLM 之前完成,安全不变式原封不动。被推迟的只有 ②。

**② 显式推迟到上生产前**,且**不靠"脱敏"解决**:规章是政策文本(如"陪产假 15 天""报销上限 5000"),这些数字本身就是答案,脱敏即毁掉可答性与条款级引用;脱敏是给 PII 用的,制度大多不含 PII。② 的正解是二选一——**私有化/VPC 部署** 或 **与厂商签 DPA + 拿到"不用你数据训练"承诺**——留给生产阶段裁定。

LLM 藏在 **`LLMClient` provider 抽象**后面:换厂商/换本地部署只动一个适配器;Seam 2 安全测试用 fake client,不出网、不花钱,并可断言送进去的 context 绝无无权内容。

## Consequences

- 嵌入(bge-m3)本地部署 → 整条链路**唯一出网点收敛到生成这一下**,② 的暴露面很小,生产合规叙事干净。
- provider 抽象让"外部 API → 私有化"成为低成本、可反悔的切换,与 ADR-0001 的安全边界一脉相承。
