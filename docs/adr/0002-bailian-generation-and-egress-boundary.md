# 回答生成使用阿里云百炼，数据出网由知识管理员判断

## Status

accepted

## Decision

V1 使用本地 `bge-m3` 生成嵌入，使用 Milvus 检索，回答生成调用阿里云百炼 API，默认模型为 `qwen-plus`。模型名称和凭据通过部署配置注入，生成能力封装在可替换适配器后。

普通用户的问题和召回的企业文档片段会发送到阿里云百炼。V1 不做数据脱敏、敏感性识别、上传审批或敏感级别字段；上传页面明确提示数据出网风险，知识管理员自行判断是否上传。

自动化测试只使用假模型，不增加真实百炼 API 连通性测试。真实通道在部署后的人工问答验收中确认。

## Considered Options

- DeepSeek API：不再是 V1 的选定供应商。
- V1 阻止敏感文档上传：没有可靠的敏感性判定能力时，技术拦截容易制造虚假的合规保证。
- 在自动化测试中调用真实模型：会引入网络、凭据、费用和非确定性，且不能替代业务边界测试。

## Consequences

- 试点环境必须展示清晰的数据出网提示，并妥善配置百炼凭据。
- 数据脱敏、敏感性校验、供应商协议或私有化部署留待后续版本决定。
- 技术日志不得记录问题正文、片段正文、完整提示词或生成文本。
